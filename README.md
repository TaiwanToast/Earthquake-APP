# 震守相助 (QuakeGuardian) 🚨

> 一款專為解決地震黃金反應時間盲區、提升災後搜救效率所設計的「智慧型行動地震預警與災後互助系統」。

## 📖 專案簡介
在突發強震面前，人類的反應時間往往只有短短數秒。「震守相助」從實際的災防痛點出發，結合即時數據串接與行動端的邊緣運算邏輯，在破壞性震波抵達前提供精準的倒數預警。

當地動山搖結束後，系統將自動啟動「安危確認與自動呼救」機制。透過綠（安全）、黃（無回應）、紅（需協助）三色狀態的視覺化災情地圖，將孤立的使用者狀態瞬間轉化為搜救單位的精準派工座標，形成一套從「震前預警」到「震後救援」的完整數位防災體系。

---

## ✨ 核心亮點功能 (Core Features)

本系統涵蓋五大核心使用案例（Use Cases），全面覆蓋災前與災後情境：

* ⏱️ **即時地震預警 (UC-01)**：接收到地震測報後，系統即時於本地端解算預估震度，並透過**語音大聲朗讀**倒數時間與震度，消除使用者的「認知真空期」。
* 🔔 **自動安危確認與防呆機制 (UC-02)**：地震結束後介面彈出確認按鈕。若使用者未動作，系統將**每 30 秒發出語音呼喊**；若超過 3 分鐘仍無回應，系統將自動將該用戶標記為「未知狀態」，防範使用者因昏迷或受困而錯失救援。
* 📍 **一鍵狀態回報與視覺化地圖 (UC-03)**：首創免繁瑣登入機制，結合 GPS 座標，將使用者狀態同步至雲端，並以「綠色（安全）、黃色（未知）、紅色（需協助）」三色標點呈現於災情地圖。
* 🚑 **搜救資訊即時整合 (UC-04)**：系統後台自動篩選紅標與黃標的異常名單，將座標與緊急聯絡資訊打包，即時推播給負責該區域的搜救人員，將「地毯式搜索」升級為「精準救援」。
* 📢 **裝置端代替呼救機制 (UC-05)**：若使用者回報「需要協助」，裝置將自動以最大音量播放求救巨響（如 Mayday 語音），協助搜救人員在粉塵瀰漫或視線不良的廢墟中進行聽音辨位。

## 🧮 邊緣運算演算法 (Edge Computing Models)

為了在行動裝置上達到極致的低延遲運算，本專案捨棄高耗能的伺服器端場址效應矩陣，導入輕量化的物理近似模型，由用戶端直接進行解算：

### 1. 預警倒數時間推算
利用 S 波平均傳遞波速（$3.5 \text{ km/s}$）推估震波抵達時間，並透過系統絕對時間相減，完美抵銷網路傳輸延遲：
$$T_{countdown} = \frac{R_{hypo}}{3.5} - (T_{current} - T_{origin})$$

### 2. 修正型地動加速度 (PGA) 衰減模型
針對台灣常見的極淺層破壞性地震，本系統改良傳統地動預估方程式，加入近斷層緩衝常數 $C=15$，並將幾何擴散衰減指數設為 $1.5$，防止近距離數值發散，精準預估當地搖晃程度：
$$PGA_{local} = PGA_{original} \times \left( \frac{D + 15}{R_{hypo} + 15} \right)^{1.5}$$
*(註：$R_{hypo}$ 為三維震源距離，$D$ 為震源深度)*

## 🎯 設計哲學與解決痛點 (UX & Design Philosophy)

本系統的設計高度以使用者為中心（User-Centered Design），針對不同人物誌（Persona）解決核心痛點：
* **針對高壓作業者（如廚師、高空建築工人）**：用語音倒數取代單純的震動，爭取 5-10 秒的黃金決策時間以關閉火源或穩住重心。
* **針對一般民眾與弱勢群體**：地震後的「自動語音呼喊」與「代替呼救巨響」，保障了受困於黑暗環境或無法動彈者的生還機率。
* **針對第一線搜救人員**：將災區混亂的資訊轉化為「紅黃綠標點地圖」，大幅縮小搜尋範圍，提升黃金 72 小時內的救援效率。

## 🛠️ 系統架構與技術棧 (Architecture)

* **Client 端 (Android)**：Java / Kotlin
* **Server 端 (Backend)**：Node.js
* **即時通訊協議**：WebSocket (`ws`) 全雙工低延遲傳輸
* **資料庫持久層**：SQLite (`sqlite3`)
* **地圖服務**：Google Maps API / Flow Positioner
